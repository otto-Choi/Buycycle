# 의사결정 기록

의사결정의 근거를 모아둔다. 새 항목은 맨 아래에 추가한다.

형식:
```
## D-번호. 제목 (YYYY-MM-DD)
- 결정:
- 근거:
- 검토한 대안:
```

## D-001. frontend/backend를 src의 상위에 둔다 (2026-11-17)
- 결정: `frontend/`, `backend/`를 루트에 두고 각각 안에 `src/`를 둔다. `package/` 폴더는 두지 않는다.
- 근거: 프론트와 백은 의존성 파일, 빌드, 배포가 각각 독립적이다.
- 검토한 대안: `src/` 아래에 frontend/backend를 두는 단일 앱 구조. 의존성이 하나인 작은 프로젝트에 적합하나, 따로 배포하기 어려워 제외.

## D-002. memory를 최상단에 두고 인덱스+주제별 파일로 관리한다 (2026-11-17)
- 결정: `memory/memory.md`에는 설명과 링크만 두고, 상세 기록은 주제별 파일로 분리한다. `CLAUDE.md`에서 `@memory/memory.md`로 참조한다.
- 근거: `.claude/memory/`는 Claude Code가 자동으로 읽는 위치가 아니라 `CLAUDE.md` 참조가 필요하다. 인덱스만 로드하면 컨텍스트를 아낄 수 있다.

## D-003. log.md 기록을 Stop 훅으로 강제한다 (2026-11-17)
- 결정: 응답 종료 시 `docs/log.md`보다 나중에 수정된 파일이 있으면 종료를 막고 기록을 요구한다.
- 근거: 규칙 문서는 Claude의 판단에 의존하지만 훅은 하네스가 실행하므로 누락을 막을 수 있다. git 커밋이 없어도 동작하도록 git 대신 파일 수정 시각을 비교한다.
- 검토한 대안: 규칙 문서만 두는 방식(누락 가능), 파일 수정마다 실행하는 PostToolUse 훅(너무 잦아 방해됨).
