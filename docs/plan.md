# Buycycle 구현 계획: ISA ETF 월초 자동 적립 매수 시스템

## Context
한국투자증권(KIS) Open API로 ISA 계좌의 ETF를 매달 초에 목표 비중에 맞춰 자동 매수한다. 저장소에는 폴더 구조와 문서 규칙만 있고 코드는 없다.

확정 사항
- 스택: Python(FastAPI) + React, 스케줄러 포함
- 주문: 완전 자동, 매수만으로 비중 맞춤, 모의투자 우선(실전은 명시적 전환)
- 월 기본 투자금 150만원, 여윳돈 추가 납입 기능
- 알림: 텔레그램 봇 (매수 계획, 매수 직전, 체결)
- 참고 자료: KIS API 가이드를 git 제외 폴더에 보관 (사용자가 "키움"이라 한 것은 오타, 한국투자증권이 맞음)
- 진행 방식: 가장 작은 단위부터 실제로 구현하고 점차 확장

## 진행 원칙
- 각 단계는 단독으로 실행·검증 가능해야 한다. 이전 단계가 끝나기 전에 다음 단계의 코드를 만들지 않는다.
- 단계가 끝나면 `docs/log.md` 기록, 선택이 있었다면 `docs/decisions.md` 추가, 커밋.
- 주문과 관련된 코드는 항상 기본값이 모의/dry-run이다.

## 단계별 계획

### 0단계: 준비 (코드 없음)
- KIS API 가이드를 `docs/reference/kis-api/`에 넣고 `.gitignore`에 `docs/reference/`를 추가한다. 저작권/민감 정보 때문에 저장소에 올리지 않으며, `README.md`에 "참고 자료는 로컬에만 있음"을 적는다.
- 모의투자 앱키 발급, `.env.example` 작성(키, 계좌번호, 텔레그램 토큰/chat id, `TRADING_MODE=paper`).
- **ISA 계좌를 API로 주문할 수 있는지 가이드로 확인한다.** 계좌상품코드와 지원 여부가 불확실한 가장 큰 위험이다. 지원하지 않으면 주문 자동화 범위를 다시 정한다. 결과를 `docs/decisions.md` D-005에 기록한다.

### 1단계: 매수 계획 계산 (가장 작은 단위, 네트워크 없음)
- `backend/src/rebalance/plan.py`의 순수 함수 `build_plan(targets, holdings, prices, cash)`.
  - 총 평가액 = 보유 평가액 + 투입 현금. 종목별 부족분 = 목표 금액 - 현재 금액.
  - 부족분이 양수인 종목에만 현금을 부족분 비율로 배분, 1주 단위 내림 후 남는 현금은 부족분이 큰 종목부터 1주씩 채운다. 매도 없음.
  - 출력: 종목별 수량, 예상 매수금액, 매수 후 예상 비중.
- 입력은 `input/targets.csv`(종목코드, 목표비중)에서 읽고, 비중 합이 100%가 아니면 오류.
- 단위 테스트(`backend/tests/test_plan.py`): 현금 부족, 1주 미만, 이미 초과한 종목, 비중 합 오류.
- 간단한 CLI로 하드코딩 시세와 보유 데이터를 넣어 계획을 출력한다.

### 2단계: 텔레그램 알림
- `backend/src/notify/`에 `Notifier` 인터페이스와 `TelegramNotifier`. 후에 다른 채널을 추가할 수 있게 분리한다.
- 메시지 3종: ① 매수 계획(종목별 예상 매수금액, 현재/목표/예상 비중) ② 매수 직전 알림 ③ 체결 알림.
- 1단계 CLI의 계획을 텔레그램으로 전송해 확인한다.

### 3단계: KIS 읽기 전용 연동 (모의)
- `backend/src/broker/kis.py`: 토큰 발급/캐시/갱신, 잔고 조회, 현재가 조회. 주문은 아직 만들지 않는다.
- 하드코딩 데이터를 실제 모의계좌의 잔고와 시세로 교체해 계획을 산출한다.

### 4단계: 주문 실행 (모의투자)
- 주문 함수와 체결 조회 추가. 안전장치:
  - 기본 `paper`. `live`는 `TRADING_MODE=live`와 별도 확인 플래그가 모두 있어야 한다.
  - 1회 총 주문금액 상한, 종목별 상한. 초과 시 주문하지 않고 알림.
  - 멱등성: 같은 달 실행 기록이 있으면 재실행 금지(DB의 월별 실행 키).
  - 미체결은 이력에 남기고 재주문하지 않는다. 모든 주문/실패를 DB와 `output/`에 기록.
- 흐름: 계획 알림 -> 직전 알림(대기 시간 설정) -> 주문 -> 체결 알림.

### 5단계: 납입 관리 (월 150만원 + 추가 납입)
- 설정 `MONTHLY_AMOUNT=1500000` (기본값). DB `contributions`에 납입 내역(정기/추가, 금액, 날짜, 사용 여부)을 기록한다.
- 추가 납입: 여윳돈이 생기면 CLI/API로 금액을 등록한다. 등록된 미사용 추가 납입금은 다음 월초 실행에서 150만원에 합산하거나, "지금 즉시 매수" 명령으로 바로 계획을 만들 수 있게 한다. 즉시 매수도 같은 안전장치와 알림을 거친다.
- ISA 연간 납입한도(제가 알기로 연 2,000만원)를 넘지 않도록 올해 납입 누계를 검사해 경고한다. 월 150만원이면 연 1,800만원이라 추가 납입 여유가 약 200만원이므로 이 검사가 중요하다. 한도 수치는 구현 시 최신 규정으로 확인한다.

### 6단계: 스케줄러
- APScheduler로 매월 첫 영업일 장 시작 후 실행. 휴장일은 다음 영업일로 넘긴다.
- 시각을 앞당겨 트리거해 같은 달 두 번째 실행이 막히는지 검증한다.

### 7단계: FastAPI + SQLite 정리
- `backend/src/api/`: 목표 비중, 보유/비중 현황, 다음 매수 계획, 추가 납입 등록, 실행 이력, 수동 실행.
- `backend/src/models/`: 목표 비중, 납입, 주문, 실행 이력.

### 8단계: React 대시보드
- `frontend/src/components/`: 목표 비중 편집, 현재 vs 목표 비중, 다음 매수 계획, 추가 납입 입력, 이력.

### 9단계: 실전 전환
- 모의투자로 최소 2회 월 사이클 검증, 상한/알림 확인 후 체크리스트를 문서화하고 전환한다.

## 수정/추가할 주요 파일

- `.env.example` (새), `README.md`, `.claude/rules/backend.md`, `frontend.md`(스택 확정 후 내용 작성)
- `docs/decisions.md`: D-004 이후 ISA 지원 여부, 알림 채널, 납입 처리 방식 등

## 검증
- 1단계: `pytest backend/tests`로 계획 계산 검증
- 2단계: 실제 텔레그램에 메시지 3종 도착 확인
- 3~4단계: 모의계좌에서 dry-run 계획 -> 실제 모의 주문 -> 잔고와 DB 이력 대조
- 5단계: 추가 납입 등록 후 다음 계획 금액이 반영되는지, 연간 한도 경고가 뜨는지 확인
- 6단계: 시각 앞당겨 트리거, 중복 실행 차단 확인
- 8단계: 개발 서버에서 화면 확인
